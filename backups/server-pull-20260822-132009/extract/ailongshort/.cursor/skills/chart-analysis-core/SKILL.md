# Chart Analysis Core

## 목적
- 차트 분석 답변을 일관된 형식으로 제공한다.
- 과장/확정 표현 없이 조건부 시나리오와 리스크를 명확히 제시한다.
- 사용자 지시 없는 기능 삭제를 방지한다.

## 필수 원칙
- 사용자의 명시 지시 없이는 기능, API, 라우트, 컴포넌트를 삭제/비활성화하지 않는다.
- `engine/`, `trading_engine/`, `lib/engine/`, `lib/core/` 분석 엔진 코드는 제거하지 않는다.
- "확정 수익", "무조건 상승", "고정 승률" 같은 표현을 금지한다.
- 분석은 투자 권유가 아니라 조건 기반 해석으로 제시한다.

## 분석 워크플로우
아래 순서를 기본으로 사용한다.

1. 시장/자산 확인  
   - 비트코인인지 주식인지, 현물/선물 여부, 거래시간 특성을 먼저 파악한다.

2. 다중 타임프레임 정렬  
   - 상위 TF(예: 1D, 4H)에서 추세/구조를 정의한다.
   - 하위 TF(예: 1H, 15m)는 상위 구조 안에서 진입 타이밍 관점으로 해석한다.

3. 구조와 유동성
   - 고점/저점 갱신, 박스/레인지, 추세선, 지지/저항, 유동성 스윕 가능성을 점검한다.

4. 보조 근거
   - 볼륨, RSI, 피보나치, 패턴(필요 시)로 구조 해석을 보강한다.
   - 지표 신호 단독 확정 해석은 피한다.

5. 시나리오 3분기
   - 상방 시나리오: 성립 조건, 목표 구간, 무효화 조건
   - 하방 시나리오: 성립 조건, 목표 구간, 무효화 조건
   - 중립 시나리오: 박스 지속/관망 조건

6. 리스크 명시
   - 변동성 확대 구간, 뉴스/이벤트, 갭/장마감 리스크를 짧게 명시한다.

## 출력 형식
가능하면 아래 형식을 유지한다.

```markdown
자산: [BTC/종목명]
기준 TF: [상위 TF / 하위 TF]

1) 구조 요약
- 현재 구조:
- 핵심 구간(지지/저항):

2) 시나리오
- 상방: [조건] -> [목표] / 무효화: [조건]
- 하방: [조건] -> [목표] / 무효화: [조건]
- 중립: [조건]

3) 리스크
- [이벤트/변동성/시간대 리스크]

4) 확인 포인트
- [다음 캔들/거래량/레벨 재테스트 등]
```

## 구현 관련 지침
- 코드 변경이 필요한 분석 기능 요청이면 먼저 `lib/analyze.ts`, `lib/indicators.ts`, `app/components/ChartView.tsx`를 확인한다.
- 변경 후 가능하면 빌드/타입 확인을 수행하고, 수행하지 못했으면 사용자에게 검증 방법을 제시한다.
